## Overview

This module documents the step-by-step procedure for enrolling client endpoints into the Wazuh security cluster. Enrolling endpoints requires installing the Wazuh agent, linking it to the manager's public endpoint, and verifying security telemetry (FIM, SCA, Vulnerabilities, Audit Logs).

For this validation, three test agents must be enrolled:
1. **Windows 10 workstation endpoint**
2. **Windows Server 2019 host**
3. **Ubuntu 22.04 LTS VM**

## Pre-conditions: Exposing the Manager Services

By default, the Wazuh Manager services inside K3s are deployed as `ClusterIP`, meaning they are only reachable internally. To allow external agents to register and ship logs, the host firewall and service routing must be opened on the GCP VM manager node.

### 1. Open Ports in Host OS Firewall (UFW)
Run these commands on the GC VM host shell to allow external agent connections (port 1514) and registration requests (port 1515):

```bash
sudo ufw allow 1514/tcp comment "Wazuh Agent Connection"
sudo ufw allow 1515/tcp comment "Wazuh Agent Enrollment API"
sudo ufw status
```

### 2. Patch Kubernetes Services to LoadBalancer
Change the services from internal `ClusterIP` to external-facing `LoadBalancer` so Klipper binds host ports 1514 and 1515 directly to the container endpoints:

```bash
# Expose agent enrollment API
KUBECONFIG=~/.kube/config kubectl patch svc wazuh-master-svc -n aml-lab -p '{"spec":{"type":"LoadBalancer"}}'

# Expose agent log shipping connection port
KUBECONFIG=~/.kube/config kubectl patch svc wazuh -n aml-lab -p '{"spec":{"type":"LoadBalancer"}}'
```

Verify that both services show an external IP binding (this will display the VM's internal node IP `10.212.0.2`, meaning ports are bound on the host public interface):

```bash
KUBECONFIG=~/.kube/config kubectl get svc -n aml-lab wazuh wazuh-master-svc
```

## Step 1 — Enroll Ubuntu 22.04 VM Agent

Execute these commands as root on the target Ubuntu 22.04 client machine:

```bash
# 1. Install Wazuh repository key
curl -s https://packages.wazuh.com/key/GPG-KEY-WAZUH | gpg --dearmor -o /usr/share/keyrings/wazuh.gpg

# 2. Add repository source list
echo "deb [signed-by=/usr/share/keyrings/wazuh.gpg] https://packages.wazuh.com/4.x/apt/ stable main" | tee -a /etc/apt/sources.list.d/wazuh.list

# 3. Install agent, passing manager address during package config
apt-get update
WAZUH_MANAGER="wazuh.aml-lab.infosecfoster.com" apt-get install wazuh-agent=4.7.5-1

# 4. Start the agent daemon
systemctl daemon-reload
systemctl enable wazuh-agent
systemctl start wazuh-agent
```

## Step 2 — Enroll Windows Endpoints (Win 10 & Win Server 2019)

Execute these commands in an **Administrator PowerShell** session on both the Windows 10 workstation and Windows Server 2019 machines:

```powershell
# 1. Download the Windows installer package
Invoke-WebRequest -Uri https://packages.wazuh.com/4.x/windows/wazuh-agent-4.7.5-1.msi -OutFile ${env:tmp}\wazuh-agent.msi

# 2. Perform silent installation pointing to the public manager FQDN
msiexec.exe /i ${env:tmp}\wazuh-agent.msi /q WAZUH_MANAGER="wazuh.aml-lab.infosecfoster.com" WAZUH_REGISTRATION_SERVER="wazuh.aml-lab.infosecfoster.com" WAZUH_AGENT_GROUP="default"

# 3. Start the agent service
Start-Service -Name "WazuhSvc"
```

## Step 3 — Centralized Configuration & Telemetry Activation

Wazuh allows configuring FIM, SCA, and log monitoring centrally from the Manager node so configuration changes do not have to be manually made on individual machines.

On the Wazuh Manager master container, open the shared agent configuration profile:

```bash
KUBECONFIG=~/.kube/config kubectl exec -it -n aml-lab deployment/wazuh-master -c wazuh-manager -- vi /var/ossec/etc/shared/default/agent.conf
```

Add the following profiles to enable the security telemetry components:

```xml
<agent_config>
  <!-- 1. File Integrity Monitoring (FIM) -->
  <syscheck>
    <disabled>no</disabled>
    <frequency>43200</frequency>
    <!-- Monitor directories in real-time -->
    <directories check_all="yes" realtime="yes">/etc,/bin,/usr/bin</directories>
    <directories check_all="yes" realtime="yes">C:\Windows\System32\drivers\etc</directories>
  </syscheck>

  <!-- 2. Security Configuration Assessment (SCA) -->
  <sca>
    <enabled>yes</enabled>
    <scan_on_start>yes</scan_on_start>
    <interval>12h</interval>
  </sca>

  <!-- 3. Process Logging (Journald for Linux) -->
  <localfile>
    <log_format>journald</log_format>
    <location>journald</location>
  </localfile>
</agent_config>
```

> [!NOTE]
> **Vulnerability Detection (CVE scans)** is configured and run on the **Manager side** rather than inside the agent. It matches agent software inventories against official database feeds.

To enable vulnerability scans on the manager, execute:
```bash
KUBECONFIG=~/.kube/config kubectl exec -it -n aml-lab deployment/wazuh-master -c wazuh-manager -- vi /var/ossec/etc/ossec.conf
```
Ensure the `<vulnerability-detector>` block is configured as follows:
```xml
<vulnerability-detector>
  <enabled>yes</enabled>
  <interval>5m</interval>
  <min_full_scan_age>6h</min_full_scan_age>
  <run_on_start>yes</run_on_start>
  <provider name="canonical">
    <enabled>yes</enabled>
    <os>jammy</os>
    <update_interval>1h</update_interval>
  </provider>
  <provider name="msu">
    <enabled>yes</enabled>
    <update_interval>1h</update_interval>
  </provider>
</vulnerability-detector>
```
Restart the Wazuh Manager to apply configuration modifications:
```bash
KUBECONFIG=~/.kube/config kubectl exec -n aml-lab deployment/wazuh-master -c wazuh-manager -- /var/ossec/bin/wazuh-control restart
```

## Step 4 — Agent Group Assignment

Assigning agents to specific logical groups (e.g., `linux-nodes` or `windows-endpoints`) can be managed through the Wazuh Dashboard:

1. Open your browser and navigate to **https://wazuh.aml-lab.infosecfoster.com**.
2. Navigate to **Wazuh** -> **Management** -> **Groups**.
3. Click **Add new group**, name the group (e.g., `workstations`), and click **Save**.
4. To assign agents to the group:
   - Go to **Wazuh** -> **Agents**.
   - Select the checkbox next to your target test agents.
   - Click **Manage groups** in the top bar.
   - Select the group and click **Assign**.
   - The agents will automatically reload and fetch the centralized configurations specific to that group.

## Step 5 — UAT / Gate Verification

### Gate 1 — Dashboard Enrollment Check
1. Open the Wazuh Dashboard interface.
2. Verify the homepage shows `Total agents: 3` and all three nodes report as **Active** status.

### Gate 2 — Linux Telemetry Alert Trigger
Run this command on your Ubuntu 22.04 client machine to create a new user:

```bash
sudo useradd testuser
```

✓ **Expected Output:**
Within 30 seconds, go to **Wazuh** -> **Security Events** -> **Events**. You should see a Level 5 alert fired:
* **Rule ID:** `5902` (User account added to the system)
* **Agent:** Ubuntu client hostname

### Gate 3 — Windows Admin Escalation Alert Trigger
Run this command in an **Administrator Command Prompt** on either Windows agent endpoint:

```cmd
net user winadmin Pass1234 /add && net localgroup administrators winadmin /add
```

✓ **Expected Output:**
Within 60 seconds, check the events console. You should see a Level 5+ security alert fired:
* **Rule ID:** `60109` (Windows: User account created)
* **Rule ID:** `60119` (Windows: User added to local administrators group)
* **Event ID:** `4720` / `4732`

### Gate 4 — File Integrity Monitoring (FIM) Real-time Alert
Edit an existing system file on the Linux client VM (e.g., hosts file):

```bash
sudo echo "127.0.0.1 test.host" >> /etc/hosts
```

✓ **Expected Output:**
Check the events console. You should see a Level 7 FIM alert fired:
* **Rule ID:** `550` (Integrity checksum changed)
* **Path:** `/etc/hosts`
* **Telemetry Data:** Shows diff values of the appended file line.
