# Sprint 1 — Module M1.2: Wazuh Manager 4.7.x 2-Node Cluster

**Platform:** Google Cloud VM (Ubuntu 22.04 LTS / K3s)
**Prepared by:** Amlak Al-Arabia General Trading Co.
**Pre-condition:** Module M1.1 (OpenSearch 2.11 Cluster) must be fully running and healthy before starting this module.

---

## Overview

This module deploys a highly available, clustered **Wazuh Manager 4.7.x** environment on K3s in the `aml-lab` namespace. 

The architecture consists of:
1. **Wazuh Master Node (`wazuh-master`):** Runs as a Deployment with 1 replica. The Master coordinates agent registration, configures the cluster database, and syncs configurations to worker nodes.
2. **Wazuh Worker Node (`wazuh-worker`):** Runs as a Deployment with 1 replica (scalable). Worker nodes receive agent log traffic, verify security events, and ship alert logs.
3. **Filebeat Sidecars:** Mounted inside both Master and Worker pods to parse `/var/ossec/logs/alerts/alerts.json` and ingest events into the OpenSearch coordinator indexer at `http://opensearch.aml-lab.svc.cluster.local:9200`.
4. **Exchange SMTP Relay:** Configured inside the Wazuh `<global>` block to alert the SOC via email for level 10+ high-severity notifications.

## Step 3 — Create Wazuh Master Deployment Manifest

Create `/opt/aml-siem/k8s/base/wazuh-manager/wazuh-master-deploy.yaml`. 

This defines the Wazuh 4.7.x container and mounts the ConfigMap files. A Filebeat container runs alongside as a sidecar, reading `/var/ossec/logs/alerts/` from a shared `emptyDir` volume:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: wazuh-master
  namespace: aml-lab
spec:
  replicas: 1
  selector:
    matchLabels:
      app: wazuh-manager
      node-role: master
  template:
    metadata:
      labels:
        app: wazuh-manager
        node-role: master
    spec:
      initContainers:
      - name: init-logs
        image: wazuh/wazuh-manager:4.7.5
        command: ["sh", "-c", "mkdir -p /shared-logs/alerts /shared-logs/archives /shared-logs/firewall /shared-logs/wazuh /shared-logs/api /shared-logs/cluster && chown -R wazuh:wazuh /shared-logs && chmod -R 770 /shared-logs"]
        volumeMounts:
        - name: shared-logs
          mountPath: /shared-logs
      containers:
      - name: wazuh-manager
        image: wazuh/wazuh-manager:4.7.5
        ports:
        - containerPort: 1514
          name: agent-conn
        - containerPort: 1515
          name: agent-auth
        - containerPort: 1516
          name: cluster-sync
        - containerPort: 55000
          name: wazuh-api
        env:
        - name: WAZUH_API_USER
          value: "wazuh"
        - name: WAZUH_API_PASSWORD
          value: "wazuh"
        volumeMounts:
        - name: config-volume
          mountPath: /wazuh-config-mount/etc/ossec.conf
          subPath: ossec.conf
        - name: shared-logs
          mountPath: /var/ossec/logs
      - name: filebeat
        image: docker.elastic.co/beats/filebeat:7.10.2
        volumeMounts:
        - name: config-volume
          mountPath: /usr/share/filebeat/filebeat.yml
          subPath: filebeat.yml
        - name: shared-logs
          mountPath: /var/ossec/logs
          readOnly: true
      volumes:
      - name: config-volume
        configMap:
          name: wazuh-master-config
      - name: shared-logs
        emptyDir: {}
```

## Step 5 — Create Services Manifest

Create `/opt/aml-siem/k8s/base/wazuh-manager/wazuh-service.yaml`. 

This defines:
1. `wazuh-master-svc`: Points to the master pod for cluster joins (port 1516) and API calls (port 55000).
2. `wazuh`: Exposes ports 1514 (agents) and 514 (syslog) across all running master/worker instances inside the cluster namespace:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: wazuh-master-svc
  namespace: aml-lab
spec:
  selector:
    app: wazuh-manager
    node-role: master
  ports:
  - port: 1515
    targetPort: 1515
    name: agent-auth
  - port: 1516
    targetPort: 1516
    name: cluster-sync
  - port: 55000
    targetPort: 55000
    name: wazuh-api
---
apiVersion: v1
kind: Service
metadata:
  name: wazuh
  namespace: aml-lab
spec:
  selector:
    app: wazuh-manager
  ports:
  - port: 1514
    targetPort: 1514
    protocol: TCP
    name: agent-conn-tcp
  - port: 514
    targetPort: 514
    protocol: UDP
    name: syslog-udp
```

Apply all the manifests:
```bash
KUBECONFIG=~/.kube/config kubectl apply -f /opt/aml-siem/k8s/base/wazuh-manager/
```

## Gate Verification Checklist

### Gate 1 — Verify cluster database joins
Run `cluster_control` inside the master pod. Both nodes must show up as `active`:

```bash
MASTER_POD=$(KUBECONFIG=~/.kube/config kubectl get pods -n aml-lab -l node-role=master -o jsonpath='{.items[0].metadata.name}')
KUBECONFIG=~/.kube/config kubectl exec -n aml-lab $MASTER_POD -c wazuh-manager -- /var/ossec/bin/cluster_control -l
```

✓ **Expected Output:**
```
wazuh-master (master) - Active
wazuh-worker (worker) - Active
```

### Gate 2 — Query Wazuh REST API
Execute an API call to query register agents. The endpoint must return valid JSON (port 55000):

```bash
TOKEN=$(KUBECONFIG=~/.kube/config kubectl exec -n aml-lab $MASTER_POD -c wazuh-manager -- curl -u wazuh:wazuh -k -s -XGET "https://localhost:55000/security/user/authenticate" | grep -o '"token":"[^"]*' | cut -d'"' -f4) && KUBECONFIG=~/.kube/config kubectl exec -n aml-lab $MASTER_POD -c wazuh-manager -- curl -H "Authorization: Bearer $TOKEN" -k -s -XGET "https://localhost:55000/agents?pretty"
```

✓ **Expected Output:**
```json
{
  "data": {
    "affected_items": [
      {
        "id": "000",
        "name": "wazuh-master",
        "ip": "127.0.0.1",
        "status": "active"
      }
    ],
    "total_affected_items": 1
  },
  "error": 0
}
```

### Gate 3 — Cluster Failover Verification
Delete the master node pod:
```bash
KUBECONFIG=~/.kube/config kubectl delete pod -n aml-lab $MASTER_POD --wait=false
```
Verify that the worker node keeps running and handles log analysis independently. Within **60 seconds**, K3s must recreate the master node pod, sync its databases, and restore green cluster metrics.

### Gate 4 — Verify High-Severity Email Alerts
Manually trigger a level 10 security alert on the host to verify Exchange relay deliveries:

```bash
# Inject a fake SSH authentication failure to trigger rule 5712 (Level 10)
KUBECONFIG=~/.kube/config kubectl exec -n aml-lab $MASTER_POD -c wazuh-manager -- logger -t sshd "Failed password for invalid user admin from 192.168.1.100 port 22 ssh2"
```

Confirm that the mail log reports successful routing to `soc@amlakalarabia.com`:
```bash
KUBECONFIG=~/.kube/config kubectl exec -n aml-lab $MASTER_POD -c wazuh-manager -- tail -n 20 /var/ossec/logs/active-responses.log
```
