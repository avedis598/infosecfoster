## Overview

This module installs Docker CE (Community Edition) on the GCP VM. Every single service in the AML-SIEM platform — OpenSearch, Wazuh, Shuffle, TheHive, Grafana, ClickHouse, and all Sprint 7 AI components — runs inside a Docker container. Getting Docker installed correctly is the most critical dependency in the entire platform.

> **Why not the Ubuntu snap version?**
> Ubuntu's default `sudo apt install docker.io` installs the snap-packaged Docker. The snap version runs in an isolated sandbox that causes subtle networking bugs — containers cannot communicate with each other correctly, volume mounts behave differently, and the Docker socket path is non-standard. These issues look like application bugs and can waste hours to diagnose. Always install from the official Docker repository.

Estimated time: 15–20 minutes.

## Step 2 — Remove Any Existing Docker Installations

Before installing from the official repo, remove any old or snap-based Docker packages that may already be present. This is safe to run even if nothing is installed — the commands simply do nothing if the packages are not found.

```bash
sudo apt-get remove -y \
  docker \
  docker-engine \
  docker.io \
  containerd \
  runc \
  docker-doc \
  docker-compose \
  docker-compose-v2 \
  podman-docker
```

Also remove any snap-based Docker if present:

```bash
sudo snap remove docker 2>/dev/null || echo "No snap docker found — OK"
```

Clean up leftover package cache:

```bash
sudo apt-get autoremove -y
sudo apt-get autoclean
```

> After this step, `docker` should not be found as a command. Verify:
> ```bash
> docker --version 2>/dev/null || echo "Docker not installed — correct"
> ```

## Step 4 — Add Docker's Official GPG Key

Docker signs its packages with a GPG key. You must add this key so apt can verify the packages are genuine and have not been tampered with.

```bash
# Create the directory for apt keyrings
sudo install -m 0755 -d /etc/apt/keyrings

# Download and store Docker's GPG key
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  -o /etc/apt/keyrings/docker.asc

# Set correct permissions on the key
sudo chmod a+r /etc/apt/keyrings/docker.asc
```

Verify the key was downloaded correctly:

```bash
file /etc/apt/keyrings/docker.asc
```

Expected output:

```
/etc/apt/keyrings/docker.asc: PGP public key block Public-Key (old)
```

---

## Step 5 — Add Docker's Official apt Repository

Add the official Docker repository to apt's sources. This points apt at Docker's own servers rather than Ubuntu's package mirrors.

```bash
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
  https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
```

Verify the file was written:

```bash
cat /etc/apt/sources.list.d/docker.list
```

Expected output (for Ubuntu 22.04):

```
deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu jammy stable
```

Update apt package lists to include the new Docker repository:

```bash
sudo apt-get update -y
```

You should see Docker's repository in the update output:

```
Get:X https://download.docker.com/linux/ubuntu jammy/stable amd64 Packages
```

## Step 6 — Install Docker CE and Compose Plugin

Install Docker CE (Community Edition), the CLI, containerd runtime, and the Compose v2 plugin all in one command:

```bash
sudo apt-get install -y \
  docker-ce \
  docker-ce-cli \
  containerd.io \
  docker-buildx-plugin \
  docker-compose-plugin
```

This may take 2–3 minutes to download and install.

**What each package does:**

| Package | Purpose |
|---|---|
| `docker-ce` | The Docker daemon — the core engine that runs containers |
| `docker-ce-cli` | The `docker` command-line tool you type commands into |
| `containerd.io` | The low-level container runtime Docker sits on top of |
| `docker-buildx-plugin` | Extended build capabilities — needed for multi-platform images |
| `docker-compose-plugin` | Compose v2 — enables `docker compose` (with a space, not a hyphen) |

Verify Docker was installed:

```bash
docker --version
```

Expected output:

```
Docker version 27.x.x, build xxxxxxx
```

Verify Compose v2 was installed:

```bash
docker compose version
```

Expected output:

```
Docker Compose version v2.x.x
```

> **Important:** The command is `docker compose` (space) not `docker-compose` (hyphen). The hyphenated version is the old Compose v1 which is deprecated. If you see `docker-compose: command not found` — that is correct and expected.

## Step 7 — Start and Enable Docker Service

Docker should start automatically after installation. Confirm it is running and set it to start on every boot:

```bash
# Start Docker service
sudo systemctl start docker

# Enable Docker to start on boot
sudo systemctl enable docker

# Check status
sudo systemctl status docker
```

Expected status output:

```
● docker.service - Docker Application Container Engine
     Loaded: loaded (/lib/systemd/system/docker.service; enabled)
     Active: active (running) since ...
```

The key lines are `enabled` and `active (running)`.

## Step 8 — Add Your User to the Docker Group

By default, Docker requires `sudo` for every command. Adding your user to the `docker` group lets you run `docker` without `sudo`.

```bash
# Add your current user to the docker group
sudo usermod -aG docker $USER
```

> **Important:** This change does not take effect in your current SSH session. You must log out and log back in for the group membership to activate.

Log out:

```bash
exit
```

Log back in from your Mac:

```bash
ssh aml-lab-01
```

Verify your user is now in the docker group:

```bash
groups
```

You should see `docker` in the list:

```
amlsiem sudo docker ...
```

Also verify with:

```bash
id | grep docker
```

## Step 9 — Configure Docker Daemon Log Rotation

Without log rotation, Docker container logs grow indefinitely and will eventually fill your disk. This is especially critical for Wazuh and OpenSearch which generate high volumes of logs.

Create the Docker daemon configuration file:

```bash
sudo nano /etc/docker/daemon.json
```

Enter the following content exactly:

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

Save and exit: `Ctrl+X` → `Y` → `Enter`

**What this configuration does:**

| Setting | Value | Meaning |
|---|---|---|
| `log-driver` | `json-file` | Stores logs as JSON files on disk (the default driver, now explicitly set) |
| `max-size` | `10m` | Each log file is capped at 10 megabytes |
| `max-file` | `3` | Keeps maximum 3 log files per container (so max 30MB per container) |

When a log file reaches 10MB, Docker rotates it — renames it and starts a new one. When there are already 3 files, the oldest is deleted. This means each container uses at most 30MB of log space regardless of how long it runs.

Verify the file was written correctly:

```bash
cat /etc/docker/daemon.json
```

Restart Docker to apply the configuration:

```bash
sudo systemctl restart docker
```

Verify Docker restarted cleanly:

```bash
sudo systemctl status docker | grep -E "Active|started"
```

Expected:

```
Active: active (running)
```

## Step 10 — Open Docker Port in UFW (If Needed)

Docker manages its own internal networking. For Sprint 1, no additional UFW ports are needed yet. However, if Docker daemon API access is needed internally:

```bash
# Do NOT open Docker daemon port 2375/2376 to the internet
# Docker's internal bridge networking works without any UFW changes
# This is just a reminder — no action needed here
echo "No UFW changes needed for Docker internal networking"
```

> Docker creates its own `docker0` bridge network interface. Containers communicate through this bridge without any firewall rules. UFW ports are only opened for services that need to accept connections from outside the VM (like Wazuh agents on port 1514, or the dashboard on port 443).

## Common Issues and Fixes

| Problem | Cause | Fix |
|---|---|---|
| `permission denied` on `docker run` | User not yet in docker group | Log out and SSH back in |
| `Cannot connect to the Docker daemon` | Docker service not running | `sudo systemctl start docker` |
| `docker compose` not found | Compose plugin not installed | `sudo apt-get install -y docker-compose-plugin` |
| `docker-compose: command not found` | Expected — v1 not installed | Use `docker compose` (with space) — this is correct |
| Docker installed but wrong version | Snap version was installed | Run Step 2 removal commands, then reinstall from official repo |
| `WARNING: No swap limit support` | GCP VMs disable swap by default | Harmless warning — can be ignored for this platform |
| Log rotation not applied to existing containers | Config only applies to new containers | Stop and restart any existing containers after changing `daemon.json` |
| `Get "https://registry-1.docker.io/...": dial tcp: lookup` | DNS resolution issue | `sudo systemctl restart systemd-resolved && sudo systemctl restart docker` |
