## Step 1 — Create the Google Cloud VM

### 1.1 — Open Google Cloud Console

Go to [console.cloud.google.com](https://console.cloud.google.com) → **Compute Engine** → **VM Instances** → **Create Instance**

### 1.2 — Configure the VM

Fill in the following settings:

| Field | Value |
|---|---|
| **Name** | `aml-lab-01` |
| **Region** | Choose closest to Kuwait (e.g. `me-central1` — Doha, or `europe-west1` for lower cost) |
| **Zone** | Any zone within the selected region |
| **Machine family** | General purpose |
| **Series** | E2 or N2 |
| **Machine type** | Minimum `e2-standard-4` (4 vCPU, 16GB RAM) — recommended `e2-standard-8` (8 vCPU, 32GB RAM) for OpenSearch |
| **Boot disk** | Click **Change** |
| **OS** | Ubuntu |
| **Version** | Ubuntu 22.04 LTS |
| **Boot disk type** | SSD persistent disk |
| **Size** | Minimum 100GB (200GB recommended for log storage) |

### 1.3 — Configure Networking

Still on the Create Instance page, expand **Advanced options** → **Networking**:

- Under **Network interfaces**, click the default interface
- Set **External IPv4 address** → click **Reserve static external IP address**
- Name it `aml-siem-ip`
- Click **Reserve**

> This gives you a permanent static IP that never changes — critical because Wazuh agents, firewall syslog sources, and client subdomains all point to this IP permanently.

### 1.4 — Configure SSH Key

Still on the Create Instance page, expand **Advanced options** → **Security**:

**On your local Mac/laptop**, generate an SSH key pair first (skip if you already have one):

```bash
ssh-keygen -t ed25519 -C "amlak-siem-admin" -f ~/.ssh/aml_siem_key
```

This creates two files:
- `~/.ssh/aml_siem_key` — your private key (never share this)
- `~/.ssh/aml_siem_key.pub` — your public key (this goes into GCP)

Copy the public key content:

```bash
cat ~/.ssh/aml_siem_key.pub
```

Back in GCP console:
- Under **SSH Keys**, click **Add item**
- Paste the entire public key content
- Click **Done**

### 1.5 — Create the VM

Click **Create** at the bottom of the page. Wait 60–90 seconds for the VM to start. You will see it appear in the VM Instances list with a green checkmark and your reserved static IP.

Note your static IP — you will use it throughout this guide. Example: `34.XXX.XXX.XXX`

## Step 2 — Configure Local SSH Access

### 2.1 — Add SSH Config Entry (on your local Mac/laptop)

```bash
nano ~/.ssh/config
```

Add these lines:

```
Host aml-lab-01
    HostName 34.XXX.XXX.XXX
    User YOUR_GCP_USERNAME
    IdentityFile ~/.ssh/aml_siem_key
    ServerAliveInterval 60
    ServerAliveCountMax 10
```

Replace `34.XXX.XXX.XXX` with your actual static IP.
Replace `YOUR_GCP_USERNAME` with your Google account username (the part before `@gmail.com`, e.g. `sanath`).

Save and exit: `Ctrl+X` → `Y` → `Enter`

### 2.2 — Set Correct Permissions

```bash
chmod 600 ~/.ssh/config
chmod 600 ~/.ssh/aml_siem_key
chmod 644 ~/.ssh/aml_siem_key.pub
```

### 2.3 — Test First Connection

```bash
ssh aml-lab-01
```

You should get a shell prompt like:

```
sanath@aml-lab-01:~$
```

If it connects — good. Type `exit` and continue to Step 3.

```bash
sudo timedatectl set-timezone Asia/Kuwait
```

Verify:

```
               Local time: Wed 2026-06-13 17:30:00 +03
```

The key lines to check:

- `System clock synchronized: yes` ✓
- `NTP service: active` ✓

> Google Cloud VMs have NTP sync enabled by default via the GCP metadata server. If `System clock synchronized` shows `no`, wait 2–3 minutes and check again — it takes a moment after VM creation.

## Step 6 — Disable Password SSH Login

> **Why:** SSH password login is vulnerable to brute-force attacks. Since you already have key-based access working (Step 2), disable passwords entirely. This is mandatory for a security product.

### 6.1 — Edit SSH Daemon Config

```bash
sudo nano /etc/ssh/sshd_config
```

Find and change these lines (use `Ctrl+W` to search):

```
# Change from:
#PasswordAuthentication yes
# To:
PasswordAuthentication no
```

```
# Change from:
#PubkeyAuthentication yes
# To:
PubkeyAuthentication yes
```

```
# Change from:
#PermitRootLogin prohibit-password
# To:
PermitRootLogin no
```

Also add this line at the bottom of the file if it does not exist:

```
ChallengeResponseAuthentication no
```

Save and exit: `Ctrl+X` → `Y` → `Enter`

### 6.2 — Restart SSH Service

> **Important:** Before restarting, open a SECOND terminal window and keep your existing SSH session open. If something goes wrong, you still have access via the existing session.

```bash
sudo systemctl restart ssh
```

### 6.3 — Verify SSH Still Works

From your **second terminal window** on your local Mac, test that key-based login still works:

```bash
ssh aml-lab-01
```

If you get a shell prompt — password login is disabled and key login works. ✓

### 6.4 — Verify Password Login is Rejected

Try to SSH with a password (this should fail):

```bash
ssh -o PreferredAuthentications=password -o PubkeyAuthentication=no aml-lab-01
```

Expected result:

```
sanath@34.XXX.XXX.XXX: Permission denied (publickey).
```

This confirms password login is disabled. ✓

## Step 7 — Configure UFW Firewall

Google Cloud has its own firewall (VPC firewall rules), but you also run UFW on the OS level for defence-in-depth. Both layers must be configured.

### 7.1 — Configure GCP VPC Firewall (Google Cloud Console)

Go to **VPC Network** → **Firewall** → **Create Firewall Rule**

Create the following rule:

| Field | Value |
|---|---|
| **Name** | `aml-siem-allow-ssh` |
| **Network** | default |
| **Direction** | Ingress |
| **Action** | Allow |
| **Targets** | All instances in the network (or specify your VM by tag) |
| **Source IPv4 ranges** | Your office/home IP only (e.g. `203.XXX.XXX.XXX/32`) — NOT `0.0.0.0/0` |
| **Protocols and ports** | TCP port 22 |

> Using your specific IP instead of `0.0.0.0/0` means SSH is only accessible from your office. This is a hard security requirement. If you need access from multiple locations, add each IP as a separate `/32` entry.

Click **Create**.

### 7.2 — Install and Configure UFW on the VM

Back in your SSH session:

```bash
# Install UFW
sudo apt install -y ufw

# Set default policies — deny all incoming, allow all outgoing
sudo ufw default deny incoming
sudo ufw default allow outgoing

# Allow SSH (port 22) — do this BEFORE enabling UFW or you will lock yourself out
sudo ufw allow 22/tcp comment 'SSH access'

# Enable UFW
sudo ufw --force enable
```

### 7.3 — Verify UFW Status

```bash
sudo ufw status verbose
```

Expected output:

```
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), disabled (routed)
New profiles: skip

To                         Action      From
--                         ------      ----
22/tcp                     ALLOW IN    Anywhere
22/tcp (v6)                ALLOW IN    Anywhere (v6)
```

Only port 22 is open. All other ports are blocked. ✓

> As you add services in Sprint 1 (OpenSearch on 9200, Wazuh on 1514, Dashboard on 443, etc.), you will add them to UFW at that time. Never open ports in advance.

## Step 8 — Configure Automatic Security Updates

Set the VM to automatically apply security patches — important for a server running unattended:

```bash
sudo apt install -y unattended-upgrades

sudo dpkg-reconfigure --priority=low unattended-upgrades
```

Select **Yes** when prompted.

Verify it is enabled:

```bash
cat /etc/apt/apt.conf.d/20auto-upgrades
```

Expected output:

```
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";
```

## Step 9 — Create a Dedicated Admin User (Optional but Recommended)

Rather than using your Google username for everything, create a dedicated `amlsiem` admin user:

```bash
# Create user
sudo adduser amlsiem

# Add to sudo group
sudo usermod -aG sudo amlsiem

# Set up SSH key for the new user
sudo mkdir -p /home/amlsiem/.ssh
sudo cp ~/.ssh/authorized_keys /home/amlsiem/.ssh/
sudo chown -R amlsiem:amlsiem /home/amlsiem/.ssh
sudo chmod 700 /home/amlsiem/.ssh
sudo chmod 600 /home/amlsiem/.ssh/authorized_keys
```

Update your local `~/.ssh/config` to use the new user:

```
Host aml-lab-01
    HostName 34.XXX.XXX.XXX
    User amlsiem
    IdentityFile ~/.ssh/aml_siem_key
```

Test login with the new user:


## Common Issues and Fixes

| Problem | Cause | Fix |
|---|---|---|
| `ssh: connect to host aml-lab-01 port 22: Connection refused` | GCP VPC firewall not configured | Add firewall rule in GCP console allowing port 22 from your IP |
| `Permission denied (publickey)` on first login | Wrong username in SSH config | Check your GCP username in IAM → it is the part before `@gmail.com` |
| `System clock synchronized: no` | VM just started | Wait 2–3 minutes and run `timedatectl` again |
| `ufw: command not found` | UFW not installed | Run `sudo apt install -y ufw` |
| SSH disconnects after enabling UFW | Port 22 not added before enabling | From GCP console, use **SSH in browser** to run `sudo ufw allow 22 && sudo ufw enable` |
| `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED` | VM was recreated with same IP | Run `ssh-keygen -R aml-lab-01` on your Mac, then reconnect |
