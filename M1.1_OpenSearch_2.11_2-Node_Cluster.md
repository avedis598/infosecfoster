# Sprint 1 — Module M1.1: OpenSearch 2.11 2-Node Cluster

**Platform:** Google Cloud VM (Ubuntu 22.04 LTS / K3s)
**Prepared by:** Amlak Al-Arabia General Trading Co.
**Pre-condition:** Sprint 0 (M0.1 to M0.5) must be fully signed off before starting this module.

---

## Overview

This module deploys a production-ready, highly available **OpenSearch 2.11.x** cluster on K3s in the `aml-lab` namespace. 
The architecture consists of:
1. **Two Data/Cluster-Manager Nodes:** StatefulSet (`opensearch-data`) backed by Persistent Volume Claims (PVC) using K3s's default `local-path` storage provider.
2. **One Coordinator Node:** Deployment (`opensearch-coordinator`) acting as a stateless search/indexing gateway that handles queries and routes alerts from the Wazuh Manager, reducing resource pressure on data nodes.

### Resource Limits and JVM Heap
* **VM Resources:** E2-standard-4 (16GB RAM, 4 vCPUs)
* **OpenSearch RAM Assignment:** Allocate 4GB RAM to the OpenSearch pods.
* **JVM Heap Rule:** Configure `-Xms2g` and `-Xmx2g` (50% of the allocated pod RAM, up to a maximum of 32GB) via environment variables to prevent JVM garbage collection pauses.

## Step 1 — Create Configuration ConfigMap

Create `/opt/aml-siem/k8s/base/opensearch/opensearch-config.yaml` to specify cluster-wide configuration settings and security flags:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: opensearch-config
  namespace: aml-lab
data:
  opensearch.yml: |
    cluster.name: aml-siem-cluster
    network.host: 0.0.0.0
    
    # Discovery Settings
    discovery.seed_hosts: ["opensearch-discovery"]
    cluster.initial_cluster_manager_nodes: ["opensearch-data-0", "opensearch-data-1"]
    
    # Disable security plugin
    plugins.security.disabled: true
    
    # Performance Optimizations
    bootstrap.memory_lock: false
    thread_pool.write.queue_size: 1000
```

## Step 3 — Create Data Nodes StatefulSet

Create `/opt/aml-siem/k8s/base/opensearch/opensearch-data.yaml`. This deploys `opensearch-data-0` and `opensearch-data-1` with dynamic volumes using K3s's built-in `local-path` storage provider:

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: opensearch-data
  namespace: aml-lab
spec:
  serviceName: opensearch-discovery
  replicas: 2
  selector:
    matchLabels:
      app: opensearch
      role: data
  template:
    metadata:
      labels:
        app: opensearch
        role: data
    spec:
      initContainers:
      # Max virtual memory maps is too low by default in Ubuntu VMs. Increase it:
      - name: init-sysctl
        image: busybox
        command: ["sysctl", "-w", "vm.max_map_count=262144"]
        securityContext:
          privileged: true
      # Clear memlock limits
      - name: init-ulimit
        image: busybox
        command: ["sh", "-c", "ulimit -l unlimited"]
        securityContext:
          privileged: true
      containers:
      - name: opensearch
        image: opensearchproject/opensearch:2.11.1
        resources:
          limits:
            memory: 4Gi
            cpu: "2"
          requests:
            memory: 4Gi
            cpu: "1"
        env:
        - name: cluster.name
          value: aml-siem-cluster
        - name: node.name
          valueFrom:
            fieldRef:
              fieldPath: metadata.name
        - name: discovery.seed_hosts
          value: "opensearch-discovery"
        - name: cluster.initial_cluster_manager_nodes
          value: "opensearch-data-0,opensearch-data-1"
        - name: node.roles
          value: "data,cluster_manager"
        # JVM Heap Config: 50% of Pod RAM limit (2GB Heap for 4GB Pod limit)
        - name: OPENSEARCH_JAVA_OPTS
          value: "-Xms2g -Xmx2g"
        - name: DISABLE_INSTALL_DEMO_CONFIG
          value: "false"
        - name: DISABLE_SECURITY_PLUGIN
          value: "false"
        securityContext:
          capabilities:
            add: ["SYS_CHROOT"]
        ports:
        - containerPort: 9200
          name: http
        - containerPort: 9300
          name: transport
        volumeMounts:
        - name: opensearch-data-storage
          mountPath: /usr/share/opensearch/data
        - name: config-volume
          mountPath: /usr/share/opensearch/config/opensearch.yml
          subPath: opensearch.yml
      volumes:
      - name: config-volume
        configMap:
          name: opensearch-config
  volumeClaimTemplates:
  - metadata:
      name: opensearch-data-storage
    spec:
      accessModes: [ "ReadWriteOnce" ]
      storageClassName: "local-path" # default K3s storage provisioner
      resources:
        requests:
          storage: 50Gi
```

## Step 4 — Create Coordinator Node Deployment

Create `/opt/aml-siem/k8s/base/opensearch/opensearch-coordinator.yaml`. Coordinator nodes handle incoming APIs and search requests, acting as log gateways:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: opensearch-coordinator
  namespace: aml-lab
spec:
  replicas: 1
  selector:
    matchLabels:
      app: opensearch
      role: coordinator
  template:
    metadata:
      labels:
        app: opensearch
        role: coordinator
    spec:
      initContainers:
      - name: init-sysctl
        image: busybox
        command: ["sysctl", "-w", "vm.max_map_count=262144"]
        securityContext:
          privileged: true
      containers:
      - name: opensearch
        image: opensearchproject/opensearch:2.11.1
        resources:
          limits:
            memory: 4Gi
            cpu: "2"
          requests:
            memory: 4Gi
            cpu: "1"
        env:
        - name: cluster.name
          value: aml-siem-cluster
        - name: node.name
          valueFrom:
            fieldRef:
              fieldPath: metadata.name
        - name: discovery.seed_hosts
          value: "opensearch-discovery"
        # Node roles: Empty tells OpenSearch to run as stateless coordinator
        - name: node.roles
          value: ""
        - name: OPENSEARCH_JAVA_OPTS
          value: "-Xms2g -Xmx2g"
        - name: DISABLE_INSTALL_DEMO_CONFIG
          value: "false"
        - name: DISABLE_SECURITY_PLUGIN
          value: "false"
        ports:
        - containerPort: 9200
          name: http
        - containerPort: 9300
          name: transport
        volumeMounts:
        - name: config-volume
          mountPath: /usr/share/opensearch/config/opensearch.yml
          subPath: opensearch.yml
      volumes:
      - name: config-volume
        configMap:
          name: opensearch-config
```

## Step 5 — Apply Manifests and Generate Internal Certificates

1. Create target configuration directories on the remote VM:
   ```bash
   mkdir -p /opt/aml-siem/k8s/base/opensearch
   ```

2. Copy the YAML configurations into `/opt/aml-siem/k8s/base/opensearch/`.

3. Generate secure nodes certificates (you can use OpenSearch's demo certificate helper to quickly bundle TLS for transport security and admin checks, or map real enterprise CA-signed certificates). 

4. Apply the resources in K3s:
   ```bash
   kubectl apply -f /opt/aml-siem/k8s/base/opensearch/opensearch-config.yaml
   kubectl apply -f /opt/aml-siem/k8s/base/opensearch/opensearch-service.yaml
   kubectl apply -f /opt/aml-siem/k8s/base/opensearch/opensearch-data.yaml
   kubectl apply -f /opt/aml-siem/k8s/base/opensearch/opensearch-coordinator.yaml
   ```

5. Watch execution until all pods show `Running`:
   ```bash
   kubectl get pods -n aml-lab -l app=opensearch -w
   ```

## Step 6 — Set Index Lifecycle Policy (ISM)

To enforce the 30-day retention rule, apply an **Index State Management (ISM)** policy to automatically delete indices matching the pattern `wazuh-alerts-*` after 30 days.

1. Create a policy JSON payload (`/tmp/ism-policy.json`):
   ```json
   {
     "policy": {
       "description": "Auto-delete Wazuh alerts older than 30 days.",
       "default_state": "hot",
       "states": [
         {
           "name": "hot",
           "actions": [],
           "transitions": [
             {
               "state_name": "delete",
               "conditions": {
                 "min_index_age": "30d"
               }
             }
           ]
         },
         {
           "name": "delete",
           "actions": [
             {
               "delete": {}
             }
           ],
           "transitions": []
         }
       ]
     }
   }
   ```

2. Push the policy definition to OpenSearch API via curl:
   ```bash
   curl -XPUT "http://opensearch.aml-lab.svc.cluster.local:9200/_plugins/_ism/policies/wazuh_retention_policy" \
     -H "Content-Type: application/json" -d @/tmp/ism-policy.json
   ```

3. Bind the retention policy to all future index patterns starting with `wazuh-alerts-*`:
   ```bash
   curl -XPUT "http://opensearch.aml-lab.svc.cluster.local:9200/_index_template/wazuh_ism_binding" \
     -H "Content-Type: application/json" -d '{
       "index_patterns": ["wazuh-alerts-*"],
       "template": {
         "settings": {
           "opendistro.index_state_management.policy_id": "wazuh_retention_policy"
         }
       }
     }'
   ```

## Gate Verification Checklist

Confirm all gates pass before moving on to Module M1.2.

### Gate 1 — Cluster health returns green
Execute a cluster health lookup against the coordinator pod interface. The status must return `"green"` and `number_of_nodes` must be `3` (2 data nodes + 1 coordinator):

```bash
curl -XGET "http://opensearch.aml-lab.svc.cluster.local:9200/_cluster/health?pretty"
```

✓ **Expected Output:**
```json
{
  "cluster_name" : "aml-siem-cluster",
  "status" : "green",
  "timed_out" : false,
  "number_of_nodes" : 3,
  "number_of_data_nodes" : 2,
  ...
}
```

### Gate 2 — Kill one data pod (yellow state check)
Simulate data pod failure. Delete data node 1:
```bash
kubectl delete pod opensearch-data-1 -n aml-lab
```
Immediately query cluster health. The status must switch to `"yellow"` (meaning primary shards are active but replicas are missing), **not `"red"`**:

```bash
curl -XGET "http://opensearch.aml-lab.svc.cluster.local:9200/_cluster/health?pretty"
```

✓ **Expected Output:**
```json
  "status" : "yellow",
  "number_of_nodes" : 2,
  "number_of_data_nodes" : 1,
```

### Gate 3 — Recover data pod (re-verify green state)
Monitor the pods until K3s spins the deleted pod back up. Within **120 seconds** after recovery, the cluster status must automatically transition back to `"green"`:

```bash
kubectl get pods -n aml-lab -w
# Wait for opensearch-data-1 to show Running / Ready 1/1

curl -XGET "http://opensearch.aml-lab.svc.cluster.local:9200/_cluster/health?pretty"
```

✓ **Expected Output:**
```json
  "status" : "green",
  "number_of_nodes" : 3,
```

### Gate 4 — Verify alerts index accepts documents
Simulate Wazuh Manager alert delivery. Write a test document to index `wazuh-alerts-30-day-test`:

```bash
curl -XPOST "http://opensearch.aml-lab.svc.cluster.local:9200/wazuh-alerts-30-day-test/_doc/1?pretty" \
  -H "Content-Type: application/json" -d '{
    "timestamp": "2026-07-17T15:25:00Z",
    "agent": { "id": "001", "name": "test-agent" },
    "rule": { "id": "100200", "description": "Test Alert Ingestion" }
  }'
```

✓ **Expected Output:**
```json
{
  "_index" : "wazuh-alerts-30-day-test",
  "_id" : "1",
  "result" : "created",
  "_shards" : {
    "total" : 2,
    "successful" : 1,
    "failed" : 0
  },
  "successful" : true
}
```

Confirm document can be read back:
```bash
curl -XGET "http://opensearch.aml-lab.svc.cluster.local:9200/wazuh-alerts-30-day-test/_doc/1?pretty"
```

Clean up the test index:
```bash
curl -XDELETE "http://opensearch.aml-lab.svc.cluster.local:9200/wazuh-alerts-30-day-test"
```
