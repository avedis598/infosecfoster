# Sprint 1 — Module M1.3: Wazuh Dashboard 4.7.x

**Platform:** Google Cloud VM (Ubuntu 22.04 LTS / K3s)
**Prepared by:** Amlak Al-Arabia General Trading Co.
**Pre-condition:** Module M1.2 (Wazuh Manager Cluster) must be fully running, healthy, and API must respond on port 55000 before starting this module.

---

## Overview

This module deploys the **Wazuh Dashboard 4.7.x** web user interface on K3s in the `aml-lab` namespace. The dashboard communicates with the OpenSearch coordinator pod to query alert indices and queries the Wazuh Manager master API to check agent registration status and perform active response triggers.

The deployment configuration consists of:
1. **Wazuh Dashboard (`wazuh-dashboard`):** Runs as a single replica Deployment using the official `wazuh/wazuh-dashboard:4.7.5` image.
2. **ConfigMap (`wazuh-dashboard-config`):** Defines the `opensearch_dashboards.yml` settings (configured to connect to the plain HTTP OpenSearch indexer) and the `wazuh.yml` settings (configured to query the Wazuh Manager API with the `wazuh:wazuh` credentials).
3. **Internal Service (`wazuh-dashboard-svc`):** Exposes TCP port 5601 inside the K3s cluster.
4. **Nginx Ingress Routing:** Exposes the dashboard frontend securely over the network via port 443 with automated Let's Encrypt TLS termination at `wazuh.aml-lab.infosecfoster.com`.

## Step 1 — Create ConfigMap for Wazuh Dashboard

Create `/opt/aml-siem/k8s/base/wazuh-dashboard/wazuh-dashboard-config.yaml`. This file configures the connection hosts for both OpenSearch (indexer) and the Wazuh API (manager):

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: wazuh-dashboard-config
  namespace: aml-lab
data:
  opensearch_dashboards.yml: |
    server.host: "0.0.0.0"
    server.port: 5601
    opensearch.hosts: ["http://opensearch.aml-lab.svc.cluster.local:9200"]
    opensearch.ssl.verificationMode: none
    opensearch.username: "admin"
    opensearch.password: "admin"
    server.ssl.enabled: false

  wazuh.yml: |
    hosts:
      - default:
          url: https://wazuh-master-svc.aml-lab.svc.cluster.local
          port: 55000
          username: wazuh
          password: wazuh
          run_as: false
```

## Step 2 — Create Service Manifest

Create `/opt/aml-siem/k8s/base/wazuh-dashboard/wazuh-dashboard-svc.yaml` to expose the dashboard port to the Ingress controller:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: wazuh-dashboard
  namespace: aml-lab
  labels:
    app: wazuh-dashboard
spec:
  selector:
    app: wazuh-dashboard
  ports:
  - port: 5601
    targetPort: 5601
    protocol: TCP
    name: http
```

## Step 3 — Create Deployment Manifest

Create `/opt/aml-siem/k8s/base/wazuh-dashboard/wazuh-dashboard-deploy.yaml`. 

> [!NOTE]
> Since the Wazuh Manager API uses self-signed SSL certificates by default, the Node.js backend of the dashboard will reject the connection with certificate authority errors. We bypass this validation inside the isolated namespace by setting `NODE_TLS_REJECT_UNAUTHORIZED: "0"`.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: wazuh-dashboard
  namespace: aml-lab
spec:
  replicas: 1
  selector:
    matchLabels:
      app: wazuh-dashboard
  template:
    metadata:
      labels:
        app: wazuh-dashboard
    spec:
      containers:
      - name: wazuh-dashboard
        image: wazuh/wazuh-dashboard:4.7.5
        command: ["/bin/sh", "-c"]
        args:
        - "rm -rf /usr/share/wazuh-dashboard/plugins/securityDashboards && exec /entrypoint.sh"
        ports:
        - containerPort: 5601
          name: http
        env:
        - name: NODE_TLS_REJECT_UNAUTHORIZED
          value: "0"
        volumeMounts:
        - name: config-volume
          mountPath: /usr/share/wazuh-dashboard/config/opensearch_dashboards.yml
          subPath: opensearch_dashboards.yml
        - name: config-volume
          mountPath: /usr/share/wazuh-dashboard/data/wazuh/config/wazuh.yml
          subPath: wazuh.yml
      volumes:
      - name: config-volume
        configMap:
          name: wazuh-dashboard-config
```

## Step 4 — Create Ingress Route Manifest

Create `/opt/aml-siem/k8s/base/wazuh-dashboard/wazuh-dashboard-ingress.yaml`. This routes external HTTPS requests on `wazuh.aml-lab.infosecfoster.com` to port 5601 of our dashboard container, automatically negotiating Let's Encrypt certificates:

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: wazuh-dashboard-ingress
  namespace: aml-lab
  annotations:
    kubernetes.io/ingress.class: nginx
    cert-manager.io/cluster-issuer: letsencrypt-prod
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    nginx.ingress.kubernetes.io/force-ssl-redirect: "true"
    nginx.ingress.kubernetes.io/proxy-body-size: 50m
spec:
  tls:
  - hosts:
    - wazuh.aml-lab.infosecfoster.com
    secretName: wazuh-dashboard-tls
  rules:
  - host: wazuh.aml-lab.infosecfoster.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: wazuh-dashboard
            port:
              number: 5601
```

## Step 5 — Deployment Commands

Run these commands to apply the dashboard configurations on the VM node:

```bash
# 1. Create target directories if missing
mkdir -p /opt/aml-siem/k8s/base/wazuh-dashboard/

# 2. Apply Kubernetes manifests
KUBECONFIG=~/.kube/config kubectl apply -f /opt/aml-siem/k8s/base/wazuh-dashboard/wazuh-dashboard-config.yaml
KUBECONFIG=~/.kube/config kubectl apply -f /opt/aml-siem/k8s/base/wazuh-dashboard/wazuh-dashboard-deploy.yaml
KUBECONFIG=~/.kube/config kubectl apply -f /opt/aml-siem/k8s/base/wazuh-dashboard/wazuh-dashboard-svc.yaml
KUBECONFIG=~/.kube/config kubectl apply -f /opt/aml-siem/k8s/base/wazuh-dashboard/wazuh-dashboard-ingress.yaml

# 3. Wait for pod initialization
KUBECONFIG=~/.kube/config kubectl wait --for=condition=Ready pod -n aml-lab -l app=wazuh-dashboard --timeout=180s
```

## Step 6 — UAT / Gate Verification

### Gate 1 — Check Ingress and HTTPS TLS Handshake
Run a curl query from your local terminal to verify that the ingress successfully routes traffic and Let's Encrypt TLS certificate issue resolves:

```bash
curl -i -k https://wazuh.aml-lab.infosecfoster.com
```

✓ **Expected Output:**
Returns `HTTP/1.1 200 OK` or `HTTP/1.1 302 Found` (redirect to login page) showing correct header payloads.

### Gate 2 — Web GUI Login
1. Open a browser and navigate to `https://wazuh.aml-lab.infosecfoster.com`.
2. Verify the browser shows a secure lock icon (valid certificate).
3. Log in using default credentials:
   - **Username:** `admin`
   - **Password:** `admin`

### Gate 3 — Verify API and Indexer Status
1. Navigate to **Wazuh** -> **Settings** -> **API Connections** inside the Dashboard.
2. Confirm the API status for the Master node endpoint shows a green checkmark indicating successful authentication.
3. Open the **Discover** module and verify that `wazuh-alerts-*` index pattern loads successfully.
