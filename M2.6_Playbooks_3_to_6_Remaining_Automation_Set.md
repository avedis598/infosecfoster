# M2.6 — Playbooks 3 to 6 — Remaining Automation Set

This guide details the implementation, configurations, and verification scenarios for Playbooks 3, 4, 5, and 6. These workflows handle admin accounts, SSL certification tracking, USB hardware mounting telemetry, and automated compliance reporting.

---

## 1. Playbook 3 — New Admin Account Created
* **Trigger:** Windows Event ID `4720` (A user account was created) or `4732` (A member was added to a security-enabled local group).
* **Actions:**
  1. Extract creation actor, target account, domain, and timestamp.
  2. Send high-priority email notification to the IT Security Manager.
  3. Create a high-priority case inside TheHive.

### Verification Scenario
* **Trigger Event:** Simulate Windows Admin Creation alert by injecting a syslog event containing the signature keywords:
```bash
python3 -c "import socket; s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM); payload = b'<189>Jul 19 06:00:00 local-agent WinEvtLog: Security: AUDIT_SUCCESS(4732): Member added to local administrators group'; s.sendto(payload, ('127.0.0.1', 514))"
```
* **Verify Output:** Inspect Mailpit for warning message and verify that a high-priority case exists in TheHive.

## 2. Playbook 4 — SSL Certificate Expiry Warning
* **Trigger:** Wazuh cert-manager checker logs or external TLS checking script.
* **Actions:**
  1. Evaluate date delta between current timestamp and certificate expiration.
  2. If delta is **30 days**, send a Warning email.
  3. If delta is **14 days**, send an Escalated Warning email.
  4. If delta is **7 days**, send a Critical Warning email and log a case in TheHive.

### Verification Scenario
* **Trigger Event:** Inject a log entry simulating certificate expiry:
```bash
python3 -c "import socket; s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM); payload = b'<189>Jul 19 06:00:00 ssl-checker: Certificate wazuh.aml-lab.amlsiem.com expires in 14 days'; s.sendto(payload, ('127.0.0.1', 514))"
```
* **Verify Output:** Verify warning email was dispatched to the Mailpit inbox.

## 3. Playbook 5 — USB Device Insertion Detection
* **Trigger:** Wazuh agent logs matching USB mount strings (Linux rule `81101`, Windows event `4307` or USB PNP logs).
* **Actions:**
  1. Extract mounted device ID, filesystem label, agent hostname, and logged-in user.
  2. Send notification email containing the device metadata to the IT compliance team.

### Verification Scenario
* **Trigger Event:** Inject a log event simulating a USB mount:
```bash
python3 -c "import socket; s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM); payload = b'<189>Jul 19 06:00:00 usb-monitor: USB device mounted: ID 0930:6545 Kingston DataTraveler, Host: MacBook-Air, User: admin'; s.sendto(payload, ('127.0.0.1', 514))"
```
* **Verify Output:** Verify compliance email contains the correct device details in the body.

---

## 4. Playbook 6 — Monthly Compliance Report
* **Trigger:** Scheduled CRON trigger (`0 6 1 * *` - 06:00 AM on the 1st day of the month).
* **Actions:**
  1. Trigger execution of `/opt/aml-siem/scripts/lifecycle/generate_report.py`.
  2. Wait for report generation to output the PDF artifact.
  3. Email the compliance PDF file to the client IT Manager.

### Verification Scenario
* **Trigger Event:** Manually trigger the scheduled cron workflow execution in the Shuffle editor UI.
* **Verify Output:** Confirm that the script executes and dispatches the compiled PDF report to the analyst email inbox.
